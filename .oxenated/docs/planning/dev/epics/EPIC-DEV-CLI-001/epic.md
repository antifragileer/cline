## Epic Overview
The Command Line Interface Foundation epic establishes the core CLI infrastructure for the GoLang Cline CLI migration. This epic provides the foundational command parsing, routing, and subcommand structure using the Cobra CLI framework. It enables users to invoke the CLI with proper arguments, discover available commands, understand usage patterns, and routes commands to appropriate handlers. This is the foundational layer upon which all other CLI functionality is built, ensuring a consistent and intuitive CLI experience that matches the existing TypeScript CLI's command structure while leveraging Go's superior performance characteristics.
[Source: .oxenated/docs/planning/cline-cli-golang-migration-prd.md:L225-L341]

## Vision & Objectives
The vision is to create a robust, fast, and intuitive command-line interface that serves as the primary entry point for all Cline functionality. By implementing the CLI foundation in Go using Cobra, we achieve faster startup times (<100ms), single-binary distribution, and consistent behavior across all platforms. The objectives include providing intuitive command routing (default task mode for direct prompts, interactive mode when no arguments provided), comprehensive help documentation, and full compatibility with existing CLI command patterns to ensure zero learning curve for existing users.

## User Journeys & Scenarios

### Primary User Journey: Command Discovery and Execution
1. New user installs Cline CLI
2. User runs `cline --help` to discover available commands
3. User runs `cline` to launch interactive mode
4. User runs `cline "prompt"` to execute direct task
5. User uses `cline task -a "prompt"` for act mode
6. User checks `cline history` to see previous tasks
7. User manages configuration with `cline config` and `cline auth`

## Technical Considerations

### Existing Code References
- **TypeScript CLI Reference**: The existing CLI at `cli/src/` serves as the functional specification but MUST NOT be imported or transpiled
- **Command Structure**: Commands must match existing CLI: `task`, `history`, `config`, `auth`, `update`, `version`, `dev`
- **State Storage**: Uses `~/.cline/data/globalState.json`, `secrets.json`, and workspace state [Source: .oxenated/docs/planning/cline-cli-golang-migration-prd.md:L64-L72]
- **gRPC Integration**: Communicates with core extension via protobuf definitions in `proto/` directory

### Proposed New Components
- **Proposed**: `cmd/cline/main.go` - Entry point for CLI application
- **Proposed**: `internal/cli/root.go` - Root command definition with Cobra
- **Proposed**: `internal/cli/task.go` - Task subcommand implementation
- **Proposed**: `internal/cli/history.go` - History subcommand implementation
- **Proposed**: `internal/cli/config.go` - Config subcommand implementation
- **Proposed**: `internal/cli/auth.go` - Auth subcommand implementation
- **Proposed**: `internal/cli/update.go` - Update subcommand implementation
- **Proposed**: `internal/cli/version.go` - Version subcommand implementation
- **Proposed**: `internal/cli/dev.go` - Dev subcommand implementation

### Dependencies
- **Cobra**: CLI framework for command parsing and help generation
- **Viper**: Configuration management (optional, for env var and config file handling)
- **Go standard library**: `os`, `flag` (via Cobra), `fmt`, etc.

## Dual Testing Considerations
This epic is subject to the dual testing mandate. All functionality MUST be tested in BOTH the existing TypeScript CLI AND the new GoLang CLI:

### Test Scenarios for Dual Testing
1. **Command Help**: `cline --help`, `cline task --help`, `cline history --help`
2. **Flag Parsing**: All flag combinations must behave identically
3. **Error Handling**: Invalid commands/flags produce same error messages
4. **Exit Codes**: Success (0) and error (non-zero) codes must match
5. **Version Output**: `cline version` format must match exactly

### Independence Verification
- [ ] No imports from `cli/src/` or `cli/package.json`
- [ ] No Node.js runtime dependencies
- [ ] No TypeScript/JavaScript code bundled in binary
- [ ] All dependencies are pure Go modules
- [ ] Build produces single static binary
[Source: .oxenated/docs/planning/cline-cli-golang-migration-prd.md:L813-L833, L1385-L1400]
