```gherkin
Feature: FEAT-ENT-AUDIT-010-EXPORT-002 - Compliance Report Generation

  Scenario: Generate compliance report in JSON format
    Given audit logs exist for the past month
    And the logs contain command executions, file edits, and API calls
    When admin runs "cline audit report --from 2024-01-01 --to 2024-01-31 --format json"
    Then report should generate in JSON format
    And include all relevant audit events from the date range
    And each entry should contain timestamp, user, action type, and result
    And the output file should be valid JSON

  Scenario: Generate compliance report in CSV format
    Given audit logs exist for the past quarter
    When admin runs "cline audit report --from 2024-01-01 --to 2024-03-31 --format csv"
    Then report should generate in CSV format
    And include column headers for all audit fields
    And all records from the date range should be present
    And the CSV should be parseable by standard spreadsheet tools

  Scenario: Filter audit logs by specific date range
    Given audit logs exist spanning multiple months
    When admin requests report for date range "2024-02-15" to "2024-02-20"
    Then only audit events from that 5-day period should be included
    And events outside the range should be excluded
    And the report metadata should indicate the filtered date range

  Scenario: Handle empty date range gracefully
    Given no audit logs exist for the requested date range
    When admin requests report for that range
    Then an empty report should generate with appropriate headers
    And a warning should indicate no events were found
    And exit code should be 0 (success, not error)

  Scenario: Export includes complete event metadata
    Given audit logs with full metadata (timestamp, user, action, result, details)
    When admin generates compliance report
    Then each entry should include timestamp in ISO 8601 format
    And user identification (username/user ID)
    And action type (command_execution, file_edit, api_call, user_action)
    And action result (success, failure, rejected)
    And relevant details (command string, file path, API endpoint)

  Scenario: Enterprise security auditor generates quarterly report
    Given the security auditor needs to review Q1 usage
    And audit logs exist for January through March
    When the auditor runs the compliance report command with quarterly date range
    Then a comprehensive report should generate
    And the report should show all commands executed, files modified, and API calls made
    And the report should include user attribution and timestamps
    And the auditor can confirm compliance with organizational policies
```

## Implementation Notes

**Audit Log Format Assumptions:**
- The feature assumes audit logs are stored in structured format (JSON Lines recommended)
- Each log entry should have standard fields: timestamp, user, action_type, result, details
- Log rotation may split files by date; reader should handle multiple files

**Report Format Specifications:**

**JSON Format:**
```json
{
  "report_metadata": {
    "generated_at": "2024-03-21T20:36:00Z",
    "date_range": {
      "from": "2024-01-01T00:00:00Z",
      "to": "2024-01-31T23:59:59Z"
    },
    "total_events": 150,
    "cli_version": "1.0.0"
  },
  "events": [
    {
      "timestamp": "2024-01-15T10:30:00Z",
      "user": "developer@company.com",
      "action_type": "command_execution",
      "action": "npm install",
      "result": "success",
      "details": {
        "working_directory": "/projects/myapp",
        "exit_code": 0
      }
    }
  ]
}
```

**CSV Format:**
```csv
timestamp,user,action_type,action,result,working_directory,exit_code,details
2024-01-15T10:30:00Z,developer@company.com,command_execution,npm install,success,/projects/myapp,0,
```
